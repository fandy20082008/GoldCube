# 漏洞提交

仓库保留的上游安全策略见[旧 AGPL 基线 SECURITY.md](https://github.com/csyqlz/VOZEB-PRO/blob/04b32d31ca00272e3866c85e9a8329036c63af72/SECURITY.md)。其中原作者邮箱和响应承诺不代表 GoldCube 当前漏洞受理渠道或 SLA。

请不要在公开 Issue 中直接发布漏洞细节、可利用代码、私密 API Key、截图中的敏感信息或真实用户数据。

## 提交流程

GoldCube 的私密报告功能和接收责任人尚待核实。渠道核实并公布前，不要把漏洞细节发送至上游邮箱或二开作者邮箱 `fandy2008_2019@qq.com`。仓库公开后，可以先开一个**不含漏洞细节**的公开 Issue，请维护者提供经过确认的私密渠道；在渠道确认之前，请勿公开 PoC、凭据或用户数据。

## 建议提供的信息

- 受影响的版本、提交、分支或部署方式。
- 清晰的复现步骤。
- 漏洞影响、攻击场景和触发条件。
- 已脱敏的日志、截图或 PoC。
- 是否涉及服务器媒体目录、API Key、AI 渠道配置或代理接口。

## 范围说明

项目会优先处理由本仓库代码或默认配置导致的 XSS、敏感信息泄露、服务器文件处理、导入导出、权限控制和供应链风险。

第三方模型服务、托管平台、浏览器插件、用户自行泄露的 API Key、没有实际利用路径的安全头建议、纯社工钓鱼或账号找回问题通常不属于本项目漏洞范围。
