# 开发来源台账与发布验收模板

使用方式：为每次引入登记来源，为每次对外服务发布复制一份发布验收表。未执行项填写“待执行”，不预先标为通过；纯独立修改不需要逐行登记。

## A. 外部材料来源台账

| 字段 | 填写值 |
| --- | --- |
| 任务/PR 编号、提交人 | 待填写 |
| 材料类型 | 代码 / 补丁 / 依赖 / 字体 / 图标 / 素材 / 文档 / 镜像 |
| 源 URL 与权利主体 | 待填写 |
| 完整 commit、版本、文件路径或镜像 digest | 待填写 |
| 本项目引入位置和用途 | 待填写 |
| 获取时适用许可证及许可文件存档 | 待填写 |
| 与旧 AGPL / 公开商用路线兼容的依据 | 待填写，不以“网上公开”替代 |
| 版权、NOTICE、源码供给及其他义务 | 待填写 |
| 是否包含新版受限内容或来源不明部分 | 待填写 |
| AI 是否处理外部材料及材料来源 | 待填写；无则写无 |
| 审核人、日期、结论 | 允许 / 拒绝 / 待确认 |
| 授权凭证位置（如适用） | 受控内部位置，勿公开合同秘密 |

## B. 发布基本信息

固定双仓映射与机器字段以[统一发布清单](dual-repository-manifest.md)为准；[源码入口设计](source-entry-design.md)定义版本展示与下载验收。每个版本保留构建前清单和补齐实际制品后的最终清单及两者原始字节 SHA-256。部署必须执行 `--phase deployment`，不能用默认 prebuild 成功代替。

| 字段 | 填写值 |
| --- | --- |
| 发布编号、日期、负责人 | 待填写 |
| 服务环境、访问对象 | 单人开发 / 组织内部 / 外部内测 / 公测 / 正式服务 |
| 固定上游 commit | 04b32d31ca00272e3866c85e9a8329036c63af72 |
| 后端仓库 / commit / tag | 待填写 |

## C. 发布前检查

每项写：通过 / 不通过 / 未知 / 有依据的不适用，并链接验证证据。失败和未知阻止新增发布。

这是对外发布的完整验收表，不是要求在隔离审计构建前已取得最终镜像证据。分别记录本地构建前条件与原始清单、构建后法律文件/组件/digest、源码公开批准、公开后匿名下载重构建和最终部署批准。真实下载验证在获准公开后执行，未知项不得预先勾选。凭据撤销/轮换与历史内容的隐私、权利和公开决定分开记录。

- [ ] 旧版基线完整 commit 已确认；仓库浅克隆和缺失对象不会使失败被误判通过。
- [ ] 已知 BUSL 切换提交未未经审核进入发布历史；人工审查覆盖复制、移植、squash 等 Git 祖先检查无法识别的路径。
- [ ] 新增外部材料有来源、明确许可及履行义务记录；无未知项。
- [ ] LICENSE、版权、修改说明及第三方声明完整且准确。
- [ ] 前端、后端、Worker 及项目配套工具的开源范围与实际发布相符。
- [ ] GoldCube 代理、品牌外壳、必要资产与安全部署/启动模板完整；跨仓组件均有源码与制品映射。
- [ ] 从干净、固定的发布提交构建，工作区未提交代码未混入制品。
- [ ] 对应源码包含必要构建/安装脚本、锁文件、配置模板和接口定义。
- [ ] 使用公开材料完成构建验证，外部服务前提和配置步骤有说明。
- [ ] 工作文件、源码包和拟发布 Git 历史完成秘密及个人数据检查。
- [ ] 源码下载免费且可用，无额外 NDA、禁止再分发或禁止商用限制。
- [ ] 页面有显著的源码获取入口，指向本项目对应版本，不只指向原作者仓库。
- [ ] 源码在用户访问新版本前或同步可得，包括外部内测和紧急修复。
- [ ] 记录版本、源码哈希、镜像 digest、验证时间和责任人。
- [ ] 两镜像采用精确 GoldCube tag 的受控手动入口，workflow/checkout/build commit 一致，自有镜像目标已授权；不存在旧标签自动发布或继承上游目标的旁路。
- [ ] GoldCube 独立仓库发布检查与跨仓映射已验收，未用应用 workflow 代替；本次若走 SSH 也保留相同供源/来源检查及主控实际批准记录。
- [ ] 版本审核证据与发布源码分开固定并校验哈希；sourceAccess、重构建和下载证据不是虚构通过或需要记录自身提交哈希的循环文件。
- [ ] 公开快照从独立新根开始，仓外双仓证明在受控 CI 变量中按原始字节 SHA-256 固定；`sourceSnapshot` 在 prebuild 中绑定证明摘要与双仓 commit，两仓实际 tree/成员/mode/归档/法律文件由独立检查核验。开发史仍以原旧基线脚本检查并保留私有证据，不把新根误报为祖先；远端变量与分支保护启用状态另行实测。

## D. 部署后核验

- [ ] 回读实际部署的前端、后端、Worker 版本和 digest，与发布清单一致。
- [ ] 回读代理 / 外壳的完整文件版本与制品清单，不能只用代理单文件哈希代表全部静态页面和资产。
- [ ] 以相应用户身份访问源码入口，确认可免费取得实际运行版本的源码。
- [ ] 核验仓库/归档中的版本和构建材料，非空包、非原作者未修改版本。
- [ ] 归档许可快照、源台账、发布验收、制品映射及回滚信息。
- [ ] 发现不一致时停止新增放量并执行预案；记录是否回滚和源码修正。

## F. 公测前一次性补审清单

- [ ] 清点实际参与内测的人，确认外部用户源码供给现状；必要时及时整改。
- [ ] 清点本地未提交内容、历史二开提交、GoldCube 前端及线上构建输入，核对人工移植来源。
- [ ] 补齐旧源码归档、可核验提交历史和许可证据；缺失处如实记录。
- [ ] 为项目自有代码建立贡献权利和许可规则，核对员工/外包/社区贡献情况。
- [ ] 发布独立二开说明，不冒充上游官方；不把旧商用授权价格说明包装为本项目报价或已取得授权。
- [ ] 将 AGENTS 规则、PR 模板、来源台账和发布清单接入实际仓库流程。
- [ ] 将规范要求转成 CI 和平台分支保护，并验证失败确实阻断。
