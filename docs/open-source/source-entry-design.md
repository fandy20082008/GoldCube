# 双仓源码入口设计

站点源码入口必须按实际运行版本提供下载；本地实现、空仓库或设计文档不能代替真实可获取的对应源码。

## 仓库映射

| 本地源码 | 唯一公开目标 | 范围 |
| --- | --- | --- |
| 主应用源码 | `https://github.com/fandy20082008/GoldCube` | VOZEB-PRO 旧基线二开主应用、前后端、Worker、文档及其构建部署材料 |
| 代理源码 | `https://github.com/fandy20082008/GoldCube-Gateway` | Node 代理、品牌外壳、必要静态资产及启动部署材料 |

两本地仓库分别配置对应 `origin`，应用原 `upstream` 保留作来源定位。远端配置不是上传授权；审核完成前不执行 push。CODEOWNERS 指向账户负责人 `@fandy20082008`，这只表示代码评审责任，不转移版权，也不证明远端保护已启用。

## 用户可见入口

在公开页页脚和已登录工作区帮助菜单提供同名“开源许可与源码”，无需付费或管理员权限。入口进入本站 `/open-source`，由发布时固定的最终清单展示当前运行版本，不能从开发分支 HEAD 动态推断。

页面展示发布标签、最终清单 SHA-256、两个仓库的完整 commit、两个完整源码包的固定 HTTPS 下载地址和 SHA-256、适用许可证及第三方声明、构建部署说明；主应用和网关角色清楚分列。下载应无需登录；浏览仓库链接应定位对应 commit，不能用浮动 main 或上游首页代替。

最终清单与公开页面只包含版本及公开证据，不暴露私密评审记录、服务器地址、凭据、客户素材或个人数据。私密证据如需引用，应先生成可公开的脱敏证明，不能把内部路径发布给用户。

## 版本绑定与验收

发布采用[统一清单](dual-repository-manifest.md)：构建前冻结来源、两仓 commit 及归档哈希，构建后补齐实际制品并执行 deployment 门禁。部署使用不可变制品，站点入口与制品在同一次发布切换，历史清单和源码包保留；回滚必须同时恢复旧清单入口及旧制品。

实现时需要验证：匿名桌面/移动入口可见；两个源码包可下载且哈希匹配；归档包含必要锁文件、配置模板和构建材料；干净环境按说明可构建；运行 app/worker digest、网关完整包哈希与清单一致。下载失败、映射不一致或缺许可材料均阻断发布。不得先上线指向空仓库的按钮，再宣称已经履行对应源码提供。

本轮实现匿名路由、首页/帮助入口及 Gateway 署名保护；运行时读取最终清单并绑定双仓运行声明，缺项不展示下载卡片。候选包与演练面向未来版本，不代表 custom.12 已供源。未上传源码或部署；首次外部访问前完成上述真实验收。
